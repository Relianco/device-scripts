# Unified installer acceptance scenarios

This matrix defines evidence required by the [architecture](../../superpowers/specs/2026-11-02-unified-installer-design.md), not completed testing. P1 is offline pure/build verification; P2 is authorized Windows VM qualification; P3 is runner coexistence; P4 is Intune lab/pilot. No live Windows tests were performed for this design.

Every case captures resolved release/configuration digests, initial observations, proposed plan, actual stages, structured result, final observations, and relevant logs. VM evidence also captures execution SID, session state, boot identity, and affected resources. Use synthetic fixtures in committed tests; retain device-specific evidence outside public source. An asserted “no mutation” needs observed command-call counts and product-state comparison, not merely an exception from a later mock.

| Combined conditions | Falsifiable expected result | Evidence and phase |
| --- | --- | --- |
| Read-only Plan, older GSA, missing replacement | Proposes remove/install with unresolved staging requirement; zero downloads, writes, UI, or process closure. | Instrumented IO/command counters; P1. |
| Unknown version plus historical success marker | `Unknown`, blocked plan; marker cannot establish compliance or absence. | Identical runtime/detector fixtures; P1. |
| Product looks compliant but prior operation has unresolved intent | Plan reports reconciliation, not `AlreadySatisfied`; product-only detection still reflects observed compliance. | Active-operation fixtures and interrupted VM run; P1/P2. |
| Damaged registration plus missing binary; ambiguous x86/x64 entries | Distinct damaged/ambiguous reasons; no choose-highest or repair inference. | State fixtures plus registry/filesystem VM mutations; P1/P2. |
| Equal/newer app, active app process, interactive profile | `AlreadySatisfied`, no prompt or installer. Exact-policy newer app rejects downgrade. | Planner call counts and VM process/UI observations; P1/P2. |
| Unsupported repair, wrong execution identity, or unsupported architecture | Fails before staging/mutation with applicability/capability reason. SYSTEM never touches user recipe HKCU. | Request fixtures, token/SID and registry audit; P1/P2. |
| Userinfo URL with empty legacy hash; corrupt downloaded or retained content | Userinfo rejected before network; bad hash terminal, no retry/removal. | Legacy/new adapter counters, deliberate byte mutation; P1/P3. |
| Malicious archive path, reparse escape, preexisting writable machine cache | No escape or privileged execution; integrity/storage preflight fails. | Hostile fixtures and real Windows ACL/reparse checks; P1/P2. |
| Arguments include quotes, empty strings, Unicode, trailing backslash, MSI syntax | Exact intended argv/property values; no new command or executable. Secret reference never appears as resolved value in outputs. | Recorder executable and log/result scans; P1/P2. |
| Journal modified to select another executable, scope, or phase | Reject/reconcile; never execute injected instruction or silently restart transaction. | State mutation tests and Windows ACL attack checks; P1/P2. |
| Two requests for different versions; old operation awaiting reboot | Exactly one active mutation; newer request receives active-operation reference. It cannot rewrite old release identity. | Concurrent processes, journal/content digests; P1/P2. |
| External MSI busy while engine lock is held | Bounded `Busy`, no other installer killed, no duplicate launch. | Controlled MSI contention and elapsed-time observation; P2. |
| GSA old/current coexist; cached bundle missing or invalid signer | No removal even if replacement is valid. | Synthetic registration plus VM cache mutation; P1/P2. |
| GSA staged successfully; network lost immediately after removal | Installation/recovery needs no network; retained closure is sufficient. If qualification fails, recipe cannot ship. | Network isolation, process trace, final bundle/files evidence; P2. |
| GSA removal returns 3010; re-entry before reboot then after reboot | Incomplete result, false detection, no same-boot repetition; after changed boot, re-detect and continue once. | Journal/boot identities, installer invocation counts, postconditions; P1/P2. |
| Removal 1641 or forced VM power loss after intent but before completion record | Reconcile actual state; no assumption command did not run, no blind removal replay. | Actual abrupt interruption, retained content, boot/process observations; P2. |
| Crash after install finished but before journal completion; child process still running in another case | First reconciles from proven postconditions; second waits/blocks rather than launching a duplicate. | Injected crash boundaries plus real child lifetimes; P1/P2. |
| Cancellation before removal; cancellation after removal; vendor timeout | First leaves original state; latter cases report incomplete/unknown as appropriate and preserve recovery content. | Command counts, elapsed time, product evidence, journal; P1/P2. |
| Installer exits 0 but target missing; installer 3010 with satisfied postconditions | First fails verification; second complete reboot. Neither is determined by exit alone. | Installer stubs and actual recipe postconditions; P1/P2. |
| UI defer, vendor 1602 cancellation, toolkit session failure, timeout 1618 | Different outcome/reason pairs retain raw code and stage; no inference of intent from bare 1602. | Supervised toolkit session and mapping fixtures; P1/P2. |
| SYSTEM with one unlocked user; then lock/logoff during welcome | Correct audience without identity change; lost eligibility prevents mutation and closure. | Session transitions, token audit, UI recording; P2. |
| Active console plus disconnected/RDP process owner; unknown presence probe | `BlockedBySession`; another user's files/processes untouched. | Multiple-session ownership and process evidence; P2. |
| No user versus OOBE/device ESP/user ESP | Only eligible machine silent work proceeds; no interactive host exit, forced closure, or local restart. | Separate enrollment/session fixtures and VM captures; P2/P4. |
| App reopens after manual closure; unsaved work; deadline expires during presentation | Recheck blocks or follows explicitly qualified policy; default never force-closes. | Process/document sentinel, deadline/clock tests; P1/P2. |
| Defer/retry within interval; same deployment new run ID; UTC deadline across DST | Stable history, bounded prompts; no “Later” without real retry owner. | Provider scheduling and toolkit history observations; P1/P2/P3. |
| 7-Zip older/same/newer, same ProductCode, stale DisplayVersion | Upgrade semantics qualified; no accidental 1638 success; runtime and detector agree. | MSI identity inspection and post-install evidence; P2. |
| VS Code standard user, second user's copy, machine coexistence, running Code | No elevation or cross-user writes; other copy not compliant; coexistence/open-process policy enforced. | Token, registry and profile diffs, binary/version evidence; P2/P4. |
| Identical resolved input built twice; target/config changed once | Byte-identical artifacts for identical input; changed detection inputs regenerate bundle, detector and metadata binding. | Digests, provenance and stale-input rejection; P1. |
| Intune detector before installation, no cache/network, 32-bit agent on x64 | Correct context/registry views; only satisfied state prints success token with exit zero and no stderr. | Generated script harness then actual IME logs; P1/P4. |
| Intune attempts GSA intermediate-reboot replacement without continuation qualification | Fails capability preflight before removal; no assertion that 3010 will resume it. | Generated metadata gate and lab invocation; P1/P4. |
| Recipe-managed replacement plus provider uninstall supersedence | Generation rejects duplicate removal ownership. Dependencies remain separately assigned and locally checked. | Metadata validation and Intune lab; P1/P4. |
| Intune generation from ensure-present-only recipe | Publication fails for missing qualified uninstall; no dummy uninstall command emitted. | Artifact generator negative fixture; P1/P4. |
| Rollout disabled while an operation is incomplete; disk retention limit reached | New deployments stop; original recovery content survives; no legacy reinstall or silent eviction. | Adapter selection and storage-pressure exercise; P2/P3. |

Critical assertions require negative controls. Remove hash comparison, change unknown to absent, drop scope/SID validation, skip postconditions, allow same-boot resume, or perturb generated detection version in a mutation run; the corresponding test must fail for the intended reason. Success because an unrelated later mock throws is insufficient.

Interruption qualification must stop real processes or power off a VM at destructive boundaries, including before process launch, during removal, after removal, during installation, and before result commit. Mocked exit codes alone cannot establish durable recovery. Repeat after mutating retained payloads and with no network. Record what was recoverable, what required intervention, and whether the UI/provider reported that distinction correctly.

P3/P4 pilots require prior P1/P2 evidence for the selected recipe and profile. Any false compliance, destructive replay, privilege escape, lost replacement payload, or unowned restart blocks phase exit. A recipe with an unresolved safety gate stays unavailable; broader rollout cannot waive it by relabeling a failure as success.
